# 飞书侧接入操作指导（一人从零完成）

> 用途：把 ZRA-3 后端从 Mock 切到真实飞书电子表格（方案A）。本文单元格/公式取自
> `agent-backend/app/modules/calculation/infrastructure/data/param_dict.json` 的 `api_cell` / `model_cell`，可直接照抄。
> 实现完可自行删除本文件。
>
> **顺序**：建应用+授权 → 建 3 张接口 sheet → 写桥接公式 → 配 META 回写 → 填配置 → 跑 PoC 逐步验。

---

## 第 1 步 · 建自建应用 + 开权限

1. 开发者后台 `open.feishu.cn` → 创建**企业自建应用**（名如「ZRA测算」）。
2. 「凭证与基础信息」→ 抄下 **App ID / App Secret**（Secret 只在创建时完整显示）。
3. 「权限管理」→ 开通两个 scope：
   - `sheets:spreadsheet`（电子表格读写）
   - `drive:drive`（云空间文件读写，含复制）
4. 「版本管理与发布」→ 创建版本 → 发布（自建应用需企业管理员通过；**scope 发布后才生效**）。

---

## 第 2 步 · 底稿 + 文件夹 + 应用授权（最易错）

1. 你的**投研测算底稿**（电子表格）就是"模板"。打开它，URL 形如 `https://xxx.feishu.cn/sheets/XXXX` → **XXXX = template_token**。
2. 云文档新建一个文件夹（如「ZRA测算副本」），打开它 URL `.../drive/folder/YYYY` → **YYYY = folder_token**。
3. **把应用加为协作者**（关键！光有 scope 不够）：
   - 底稿右上「分享 / …」→ 添加协作者 → 搜索你的应用名 → 设**可编辑**；
   - 副本文件夹同样 → 添加应用为**可编辑**。
   - 漏这步：即便开了 scope，复制/读写也会返回无权限（PoC 第 ①/② 步会报）。

---

## 第 3 步 · 底稿里新建 3 张接口 sheet

新建 3 张工作表，名字**必须正好是**：`API_INPUT`、`API_OUTPUT`、`API_META`（适配器按这名字解析 sheetId）。

---

> 共 32 个输入格，其中 31 条有桥接（node_name 无模型格，不桥接）。

> **中长期充/放均价（B32/B33）—— 值从哪来**：来源在**后端 json**（常量表，目前仅宁夏有值，
> 其余省为空），由系统写入 API_INPUT。你只在模型格 `输入1-基础参数!D32/D33` 填桥接公式
> `=API_INPUT!B32` / `=API_INPUT!B33` 即可，**不要**在底稿里硬编码或按省 VLOOKUP。

> **⚠ 关于 9 个开关（B18:B26）与两档收益（B27:B29）—— 值从哪来（PRD §四来源 / 规则3）**
> 这些格的**值由后端按省份查《表2 各省收益结构》算出后写入 API_INPUT**，PRD 原文："**表2取数由本系统后端做**"。
> 所以你搭底稿时：
> - **不要**在这些格里硬编码 1/0 或某省的固定值；
> - **不要**在底稿里对这些格做"按省份 VLOOKUP 表2"——那是后端的活，底稿里做会与系统写入冲突；
> - **只做桥接**：模型开关格（如 `输入1-基础参数!D29`）填 `=API_INPUT!B18`，运行时由系统按省份填 1/0（开关=0 也会写）。
> 两档收益（中长期/调频/干预首年收益 B27:B29）同理，是后端按表2合并表头公式+项目时长算出后写入。
>
> 你说的"**有限选项按省份不同**"是**前端调整区**的事（PRD US-1.3：除现货外，中长期/调频/干预/容量/租赁按该省表2开关=1 才显示可改，改省份→后端重拉表2→重算显隐），由后端 `switches` 输出支撑、前端 Batch4/5 消费，**与你现在搭 API_INPUT 模板无关**。

| B4 | 资本金IRR | `=输出-财务指标汇总表!D19` |

| B6 | 年均利润 | `=输出-财务指标汇总表!D14` |
| B7 | 首年总收入 | `=营业收入、税金及附加!C4` |
| B8 | 首年电能量收益 | `=营业收入、税金及附加!C6` |
| B9 | 首年容量市场收益 | `=营业收入、税金及附加!C17` |
| B10 | 首年调频市场收益 | `=营业收入、税金及附加!C11` |
| B11 | 首年租赁市场收益 | `=营业收入、税金及附加!C10` |
| B12 | 首年干预补偿收益 | `=营业收入、税金及附加!C15` |
| B13 | 首年补贴收入 | `=营业收入、税金及附加!C12` |
| B14 | 充电成本 | `=XLOOKUP(输入1-基础参数!D27, 地区!A3:A50, 地区!Z3:Z50)` |
| B15 | 放电返还 | `=XLOOKUP(输入1-基础参数!D27, 地区!A3:A50, 地区!AA3:AA50)` |
| B16 | 损耗费用 | `=XLOOKUP(输入1-基础参数!D27, 地区!A3:A50, 地区!Y3:Y50)` |
| **C2:Q2** | 主营业务成本(15年序列) | C2 填 `=成本费用表!D4`，向右拖到 Q2 |
| **C3:Q3** | 当期还本付息(15年序列) | C3 填 `=还本付息!D6`，向右拖到 Q3 |
| **C4:Q4** | 资本金净现金流(15年序列) | C4 填 `=资本金现金流量表!E18`，向右拖到 Q4 |
| **C5:Q5** | 全投资所得税后净现金流(15年序列) | C5 填 `=全投资净现金流量!D22`，向右拖到 Q5 |

> 共 19 个输出：15 个标量（B2:B16）+ 4 条 15 年序列（C2:Q2 / C3:Q3 / C4:Q4 / C5:Q5）。
> 序列的源区间各 15 列（如 `成本费用表!D4~R4`），拖拽后核对末列对齐。
> **B14/B15/B16 地区成本**：按省份(`输入1-基础参数!D27`)在『地区』sheet 用 XLOOKUP 取——
> 充电成本=**Z列**（过网费）、放电返还=**AA列**（返还费）、损耗费用=**Y列**（过网费损耗）。
> 这三列底稿已内置"按并网电压 D7 选列"逻辑（110kV→T/U，220kV→W/X 段），所以**直接引用 Z/AA/Y 即可，
> 别自己引 T/U/W/X**（否则 110kV 会取到 220 段的值）。电压 D7 由系统写 `API_INPUT!B6`→桥接 `=API_INPUT!B6` 驱动。

### ③ API_META（回写）

| 格 | 用途 | 怎么填 |
|---|---|---|
| B1 | status | 填公式 `=IF(输出-财务指标汇总表!D15<>"","done","computing")`（关键结果算出即 done） |
| B2 | request_id | **留空**，系统写入，勿填公式 |
| B3 | param_hash | **留空**，系统写入，勿填公式 |

> **原“只读展示”5 项现已全部进接口区**：中长期充/放均价 → API_INPUT!B32/B33（系统写入）；
> 地区成本三项（充电成本/放电返还/损耗）→ API_OUTPUT!B14/B15/B16（模型『地区』sheet 按省算出、系统读回）。
> 所以底稿模型里 `输入1-基础参数!D32/D33` 填 `=API_INPUT!B32/B33`，`API_OUTPUT!B14/B15/B16` 填引用『地区』sheet 的桥接公式即可。

## 第 5 步 · 填配置（测试环境可直接写 `application.yml`）

测试环境**推荐直接填** `configs/application.yml` 的 `feishu` 段（改完重启后端即生效）：

```yaml
feishu:
  enabled: true
  app_id: "cli_xxx"           # 自建应用 App ID
  app_secret: "xxx"           # 自建应用 App Secret
  template_token: "底稿的 sheets token"
  target_folder_token: "副本文件夹 token"
```

> 生产环境别把凭据提交进仓库——改走 Nacos/环境变量。环境变量（Windows cmd）等价写法：
> ```
> set IR_FEISHU_ENABLED=true
> set IR_FEISHU_APP_ID=cli_xxx
> set IR_FEISHU_APP_SECRET=xxx
> set IR_FEISHU_TEMPLATE_TOKEN=底稿的 sheets token
> set IR_FEISHU_FOLDER_TOKEN=副本文件夹 token
> ```
> 环境变量优先级高于 `application.yml`（有则覆盖）。

API_META 三格用默认 `API_META!B1/B2/B3`（与上一致），无需额外配；若你改了 sheet 名或格位，
同步改 `configs/application.yml` 的 `feishu.meta_*` 与 `param_dict.json` 的 `api_cell`。

## 第 6 步 · 跑 PoC，逐步验证

```
.venv\Scripts\python.exe tools\feishu_poc.py
```

按它报的步骤修：

| 报错 | 多半原因 |
|---|---|
| ① copy 失败 | 应用没加为底稿/文件夹协作者，或 `drive:drive` 没发布 |
| ② 写入失败 | API_INPUT 的 sheet 名/单元格与本文表不一致 |
| ③ 一直 computing / 超时 | B1 的 status 公式没配好，或输入桥接没通（模型没算） |
| ④ read_output 空/错 | API_OUTPUT 单元格或输出桥接公式问题 |
| ✅ 全通 | 真链路 OK，`/tasks` 接口即刻连真飞书 |

## 一致性 & 隐患提醒

1. **地址一致性**：本文地址来自 `param_dict.json` 的 `api_cell`。完全照表建 → 代码零改；
   若你挪了某格，就同步改 `param_dict.json` 里那条的 `api_cell`（改数据不改码）。
2. **模型格以底稿为准**：`model_cell`（如 `输入1-基础参数!D3`）是设计对底稿的假设；
   以你底稿真实格为准——尤其 sheet 名「输入1-基础参数/技术参数」是挂账 #5 待核对项，两边对齐即可。
3. **防串号（够用，含隐患）**：飞书写入即同步重算，系统写完 API_INPUT 立即读、状态一致；
   当前 `read_meta` 读回 B2（系统自己写的 request_id）即匹配，够用。若日后发现是**异步重算**，
   需在输出侧加一个"算完才回显 request_id"的格——那时找开发加（挂账 #2 的一部分）。
