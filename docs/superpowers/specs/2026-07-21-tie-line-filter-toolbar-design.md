# 联络线地图筛选工具栏重构设计

## 背景

联络线地图顶部筛选区当前仍呈现传统表单拼接感：原生 select、双 number input、交换按钮和重置按钮的系统边框较明显，容量上下限常驻顶部造成视觉零碎，重置按钮权重偏高。此次重构只调整筛选区域表现与局部交互承载，不改变筛选状态、筛选逻辑、交换逻辑、重置逻辑和地图刷新行为。

## 目标

- 将顶部筛选区重构为一条轻量、连续的分析工具栏。
- 统一控件高度、圆角、边框、字体、hover 和 focus-visible 状态。
- 起点、终点、容量筛选形成紧凑组合，避免“标签在上、控件在下”的表单感。
- 容量筛选从常驻双输入框改为一个触发器，具体输入收进 Popover。
- 重置筛选降级为次级图标操作，仅在存在有效筛选时可点击。
- 在工具栏右侧提供轻量筛选结果反馈。

## 范围

本次主要修改 `agent-frontend/src/views/tie-line/components/TieLineFilterBar.vue` 及其相关前端测试。必要时允许在父级页面传入展示用的可见线路数和总线路数，但筛选计算位置不迁移、不重写。

不在本次范围内：

- 不调整后端接口或数据契约。
- 不改 Pinia store 的筛选规则。
- 不改地图线路渲染、选中、详情推荐逻辑。
- 不新增登录、鉴权或路由守卫。
- 不引入新的业务参数或容量计算规则。

## 结构设计

顶部区域保持两行层级：

```text
跨省跨区联络线    41条线路 / 25个区域 / 15个电压等级 / 148,400 MW
[起点 全部地区 ▼] [交换图标] [终点 全部地区 ▼] [额定容量 不限 ▼] | 显示 41 条线路 [重置图标]
```

筛选栏使用 `.tl-filterbar` 作为轻量容器，内部划分：

- `.tl-filterbar__primary`：起点、交换、终点、容量。
- `.tl-filterbar__actions`：筛选结果文本、重置按钮。

筛选栏不使用厚重卡片、不添加大阴影、不为每个筛选项增加独立标题行。控件之间通过统一高度、统一圆角、统一边框和 8px 间距建立整体感。

## 控件设计

### 起点和终点

起点和终点使用同一种 `.tl-filter-control`：

- 高度 34-36px。
- 圆角 6px。
- 边框使用低对比度中性色，优先采用 `rgba(15, 23, 42, 0.12)` 或映射到现有 XC token。
- 背景为白色或 `rgba(255, 255, 255, 0.82/0.88)`。
- 左侧内嵌标签分别为“起点”“终点”。
- 空选项文案为“全部地区”。
- 原生 select 边框和箭头隐藏，右侧使用 `ChevronDown` 图标。
- 行政区名称不省略；宽度不足时通过控件最小宽度和响应式换行解决。
- 起点和终点宽度一致。

当起点或终点存在筛选值时，对应控件进入激活态，边框使用页面强调色或 `--xc-border-accent`，但不使用高饱和填充背景。

### 交换按钮

交换按钮改为轻量图标按钮：

- 使用 `ArrowLeftRight` 图标。
- 固定 32×32px。
- 默认透明背景、无边框。
- hover 时显示浅色圆角背景，文字/图标色加深。
- 保留 `aria-label="交换起点和终点区域"`。
- Tooltip/title 文案为“交换起点与终点”。
- 点击后添加约 200ms 的 180 度旋转反馈动画。
- 继续只派发 `swap-regions`，不在组件内改写起终点状态。

### 容量筛选

容量筛选顶部只展示一个触发器：

- 未筛选显示“额定容量 不限”。
- 两端均存在时显示如 `2,000-5,000 MW`。
- 只有上限时显示如 `≤ 2,000 MW`。
- 只有下限时显示如 `≥ 5,000 MW`。
- 有任一容量边界时进入激活态。

点击触发器打开 Element Plus Popover，Popover 内包含：

```text
额定容量范围（MW）
[最低容量] — [最高容量]

常用范围
[≤ 2,000] [2,000-5,000] [≥ 5,000]

[清除] [确定]
```

交互规则：

- Popover 内输入使用组件本地临时状态，用户输入过程中不立即改变外部筛选条件。
- 点击“确定”后派发 `update:min-capacity-mw` 与 `update:max-capacity-mw`，由父级现有逻辑刷新可见线路。
- 点击常用范围只更新临时输入，等待用户点击“确定”应用。
- 点击“清除”清空临时输入，并立即派发空容量边界，关闭或保留 Popover 均可，推荐关闭以表达已完成清除。
- number input 保留 `type="number"`、`min="0"`、`step="1"`、`inputmode="numeric"`，但通过 CSS 隐藏原生上下箭头和 inset 边框。
- 不在组件内重写容量倒置范围处理；继续依赖现有父级/store 的闭区间、非负整数、空容量排除和倒置范围自动交换逻辑。

### 重置按钮

重置按钮降级为图标按钮：

- 使用 `RotateCcw`。
- 固定 32×32px。
- 默认透明背景、无边框。
- Tooltip/title 文案为“重置筛选”。
- 无筛选条件时 disabled，降低透明度，不能点击。
- 存在任一有效筛选条件时启用，并提高图标对比度。
- hover 时显示浅色背景，不使用实色按钮、大边框或系统 outset 边框。
- 点击后继续只派发 `reset-filters`。

### 筛选结果反馈

在重置按钮左侧显示 12px 次级文字：

- 无筛选：`显示 41 条线路`。
- 有筛选：`显示 8 / 41 条线路`。
- 无匹配：`未找到符合条件的线路`。

结果反馈不做彩色徽章或胶囊，不使用红色错误提示。

## 数据与事件

组件继续保持受控接口：

- `startRegion`
- `endRegion`
- `minCapacityMw`
- `maxCapacityMw`
- `regionOptions`

事件继续保持：

- `update:start-region`
- `update:end-region`
- `update:min-capacity-mw`
- `update:max-capacity-mw`
- `swap-regions`
- `reset-filters`

为展示筛选结果，允许增加纯展示 props，例如：

- `visibleCount`
- `totalCount`

这两个 props 只用于文案展示，不参与筛选计算。

## 响应式设计

- 宽度充足时保持单行布局。
- 约 1366px 宽度下，起点、交换、终点、容量、结果和重置应完整展示。
- 宽度不足时 `.tl-filterbar` 允许换行。
- 起点、交换、终点作为同一主筛选组保持邻近，不让交换按钮脱离起终点。
- 更窄屏幕下，结果和重置可移到第二行右侧。
- 不通过极度压缩控件宽度来省略行政区名称，不产生横向滚动条或控件重叠。

## 样式约束

- 禁止出现浏览器原生 select 灰色直角边框。
- 禁止 number input 出现 inset 内凹边框。
- 禁止交换和重置按钮出现 outset 系统边框。
- hover 时边框略微加深。
- focus-visible 使用项目强调色焦点环。
- 尽量使用现有 XC token；如需 rgba 中性色，应仅限于低对比边框、浅背景和 hover 背景。
- 不使用大量黄色或高饱和激活背景。

## 测试与验证

更新 `agent-frontend/tests/tie-line-filter-bar.spec.js`，覆盖：

- 起点和终点 select 仍派发原更新事件。
- 交换按钮仍派发 `swap-regions`。
- 重置按钮在无筛选时禁用，在有筛选时启用并派发 `reset-filters`。
- 容量 Popover 的“确定”派发原容量更新事件。
- 容量 Popover 的“清除”派发空容量边界。
- 容量显示文案覆盖“不限”、闭区间、仅上限、仅下限。
- 筛选结果文案覆盖无筛选、有筛选、无匹配。
