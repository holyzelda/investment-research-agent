# 政策与市场历史研究记录硬删除设计

## 目标

允许用户在政策与市场页面的“研究案卷 / 历史研究记录”中永久删除本人不再需要的单条咨询记录。删除需经明确确认，并同步从前端状态和数据库中移除。

## 范围与边界

- 仅覆盖政策与市场咨询记录，不影响首页会话历史、市场资讯或其他业务模块。
- 采用硬删除：确认后从 `consultation_records` 表物理删除，删除后不可恢复。
- 仅允许删除当前平台用户拥有的记录；不存在或不归属当前用户的记录统一返回 404。
- 本次不引入软删除字段、恢复入口、批量删除或第三方依赖。

## 用户流程

1. 用户将鼠标悬停在一条历史研究记录上，或使用键盘 Tab 聚焦到该记录时，显示删除图标按钮。
2. 用户点击删除图标。该点击必须停止事件传播，不触发当前记录的选中或打开操作。
3. 前端弹出 Element Plus 确认框：标题“删除历史研究”，内容“删除后无法恢复，确认删除吗？”，提供“删除”和“取消”。
4. 用户取消时，不修改任何前端状态或数据库记录。
5. 用户确认时，前端请求 `DELETE /ir/policy-market/consultations/{id}`。
6. 后端以 `id + 当前 user_id` 联合条件执行物理删除并提交事务。
7. 成功后，前端删除历史列表项与详情缓存，并显示“已删除”。若被删记录正处于阅读态，则清空选中记录，回到新建提问态。
8. 请求失败时，前端保留列表与阅读状态，并显示服务端错误信息或“删除失败”。

## 后端设计

### HTTP 契约

新增端点：

```http
DELETE /ir/policy-market/consultations/{record_id}
```

成功响应继续使用统一响应壳：

```json
{
  "code": 200,
  "msg": "success",
  "data": { "id": 123, "deleted": true }
}
```

如果记录不存在或不属于当前用户，返回 404，不泄露记录归属信息。

### 分层职责

- `interface/router.py`：解析路径参数和当前平台用户；调用应用服务；无匹配记录时抛出 `NotFoundException`；成功后提交事务并返回 `ok()` 响应壳。
- `application/consultation_service.py`：提供按用户删除咨询记录的应用服务方法。
- `domain/ports.py`：声明 `delete_by_id_and_user(record_id, user_id)` 仓储端口。
- `infrastructure/persistence/consultation_repository.py`：以 SQLAlchemy `DELETE` 并附带 `id` 与 `user_id` 条件执行硬删除，使用受影响行数表达是否删除成功。

不改 ORM、DDL 或 migration：数据表已有满足硬删除所需的主键及用户归属字段。

## 前端设计

### 组件

`ConsultationHistory.vue` 在每个历史条目中加入独立删除按钮：

- 仅在条目 `:hover` 或内部元素 `:focus-within` 时视觉显示；无障碍树中始终具有可访问名称“删除研究记录”。
- 按钮拥有独立焦点样式，支持 Tab / Enter / Space 操作。
- 删除图标的点击处理使用 `.stop`，不触发条目自身的选择事件。
- 组件新增 `delete` 事件，只上报记录 ID；不承担确认弹窗或网络请求。

### 页面与状态

- `index.vue` 接收 `delete` 事件，以现有 Element Plus `ElMessageBox.confirm` 和 `ElMessage` 模式负责确认、成功和失败反馈。
- `policyMarket` Pinia store 提供 `removeConsultation(id)`：先调用 API；成功后更新 `consultations`、删除 `consultationDetails[id]` 缓存；若删除对象等于 `selectedConsultationId`，清空该选中值。
- `policyMarket.js` 对尚未持久化的 `pending-*` 临时记录不调用后端删除接口，直接从前端状态移除；这保证处理中或失败的本地占位项也可以被用户清理。
- `policyMarket.js` 新增 `deleteConsultation(id)` API 封装，对应上述 DELETE 端点；请求工具仍返回完整响应壳后按当前 API 模式解包 `data`。

## 状态与异常

| 场景 | 预期行为 |
| --- | --- |
| 未悬停、未聚焦 | 删除图标不显示；历史记录列表保持现有外观。 |
| 悬停或聚焦 | 显示可点击、带可访问名称的删除图标。 |
| 取消确认 | 不发送请求、不更新列表。 |
| 删除非当前项成功 | 移除该项及缓存，保持当前阅读项和页面位置。 |
| 删除当前阅读项成功 | 移除该项及缓存，清空选中 ID，页面回到新建提问态。 |
| 请求 404 | 保留当前列表与状态，提示记录不存在或无权限。 |
| 网络或服务端错误 | 保留当前列表与状态，提示删除失败。 |
| `pending-*` 本地记录 | 仅清理前端临时记录，不发起 DELETE 请求。 |

## 测试与验收

### 后端

- 成功删除当前用户的记录，验证数据库中记录已不存在且响应为 `{id, deleted: true}`。
- 删除不存在记录返回 404。
- 用户 A 不能删除用户 B 的记录，返回 404，且用户 B 的数据库记录仍存在。

### 前端

- 历史条目渲染删除按钮并发出 ID；删除按钮点击不发出 `select`。
- 取消确认时不调用 Store 删除操作。
- 确认后调用 Store 删除操作并显示成功提示。
- Store 成功删除后移除列表项及详情缓存；删除当前选中项后重置阅读态。
- API 删除请求使用正确的 DELETE URL 和方法。

### 人工验收

- 悬停和键盘聚焦均可发现并操作删除按钮。
- 删除其他记录不会切换当前阅读内容。
- 删除当前记录后显示新建提问界面。
- 刷新页面后，已删除记录不再从数据库加载。
