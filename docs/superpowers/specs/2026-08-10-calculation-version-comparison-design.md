# 测算版本差异与项目档案摘要设计

## Problem Statement

当前对话界面可以展示每次测算的基本信息、核心结果和图表，也能通过 V1、V2、V3 区分测算版本。但当基本项目信息不变、仅修改可调整参数或高级参数时，用户无法从结果卡片和右侧项目档案快速识别不同测算版本的差异。

系统已经为每次成功测算保存冻结入参和结果快照。本设计在不重复展示参数调整模块的前提下，将版本差异提炼到结果卡片，并将右侧项目档案收敛为低高度、可识别、只负责跳转的版本摘要。

## Goals

- 让用户在结果卡片中快速看出当前版本相对任意历史版本的参数差异。
- 默认将当前版本与紧邻上一版比较，同时允许选择当前版本之前的任意版本。
- 在当前访问期间记住每个版本的比较选择；刷新或重新打开会话后恢复默认上一版。
- 区分用户主动调整和系统联动更新，避免把自动重算误认为用户直接修改。
- 在五项核心投资收益指标卡内显示结果变化，用趋势折线箭头和经济含义颜色表达。
- 保持收益环形图和现金流图的现有展示，不增加文本对比结论。
- 让右侧项目档案以固定的“Vn 较 Vn-1”口径展示紧凑摘要，不受主结果卡临时比较对象影响。
- 保持右侧项目全投资 IRR 为卡片最显眼的结果识别数字，并控制单条记录高度。

## Non-goals

- 不在参数调整模块中再增加一份版本差异表。
- 不在右侧项目档案中提供比较版本切换、抽屉或完整差异详情。
- 不在右侧档案中展示 IRR、回收期或利润的版本差值。
- 不对收益环形图或现金流图叠加第二版本、差异文本或比较图层。
- 不改变测算公式、参数字典、结果快照原始数值或已有报告生成流程。
- 不把正式报告历史与测算版本差异混为一体。

## Terminology

- **当前版本**：正在结果卡片中查看的测算版本，例如 V3。
- **比较版本**：结果卡片中用于计算参数差异和指标差异的历史版本。
- **上一版**：当前版本按会话版本顺序的直接前一个成功测算版本，例如 V3 的上一版是 V2。
- **主动调整**：用户在本次重新测算请求中直接提交并最终生效的可调整参数。
- **联动更新**：未被用户本次直接提交，但因项目条件、依赖关系或系统重算而在本次最终冻结入参中变化的参数。
- **右侧固定口径**：右侧档案永远将 Vn 与 Vn-1 比较，仅用于生成版本来源摘要。

## Design

### 1. Result card comparison control

结果卡片顶部在版本和测算时间附近增加“对比版本”选择控件。

```text
测算完成 · V3
甘肃省储能项目测算结果
测算时间 2026年08月10日 14:32:06       对比版本 [V2 · 上一版 ▾]
```

规则：

- 默认选择紧邻上一版。
- V1 没有历史版本，不显示比较控件，并显示“首个测算版本”。
- 当前版本不能选择自己或未来版本。
- 选项按当前会话中更早的成功版本排序，至少包含版本号和必要的项目识别信息。
- 用户切换比较版本后，参数差异和核心指标差异同步更新。
- 每个当前版本在当前页面访问期间保存自己的比较版本选择。
- 切换右侧档案记录只定位到该版本结果；若该版本在当前访问期间已有选择，则恢复该选择，否则默认选择它的上一版。
- 刷新页面或重新打开会话时不恢复临时选择，所有版本重新采用上一版作为默认比较对象。

### 2. Version difference summary

结果卡片增加“版本变化”模块。它只展示当前版本和比较版本之间发生变化的最终冻结参数，不复制参数调整模块的编辑能力。

变化按照以下类别分组：

1. 项目基本信息
2. 可修改参数
3. 高级参数

每个变化行包含：参数名称、比较版本旧值、当前版本新值、变化来源。

```text
版本变化                                      较 V2 · 4 项变化

高级参数 2 项
运营期                         15 年  →  20 年       主动调整
策略达成率                     90%    →  85%         主动调整

可修改参数 2 项
现货充电均价                   0.3281 →  0.3415       联动更新
现货放电均价                   0.6120 →  0.5984       联动更新
```

展示规则：

- 只展示发生变化的字段。
- 没有变化的类别不展示。
- 类别标题的数量表示该类别发生变化的字段总数。
- `主动调整`使用信息蓝色；`联动更新`使用提示橙色。
- 当最终入参没有变化时，显示“与比较版本参数未变化”。
- 差异判断使用规范化后的参数值，避免数值类型或展示精度差异造成虚假变化。
- 结果卡片中不限制每个类别展示数量；主卡用于完整解释差异。

#### Source attribution

后端或任务快照必须可靠保存本次主动提交的参数键集合，不能仅通过比较前后最终入参推测来源。

建议每次成功测算的输入快照增加轻量来源信息：

```json
{
  "minInput": {},
  "apiInput": {},
  "changeMeta": {
    "previousTaskId": 123,
    "explicitOverrideKeys": ["operation_years", "strategy_achievement_rate"],
    "derivedChangedKeys": ["spot_charge_avg", "spot_discharge_avg"]
  }
}
```

其中：

- `explicitOverrideKeys` 是本次请求中用户明确提交并最终生效的参数键。
- `derivedChangedKeys` 是未被本次明确提交、但相对上一版本最终值发生变化的键。
- 首次测算没有上一版本，`changeMeta` 可为空或标记为 `initial`。
- 前端只展示经过后端分类后的字段，不自行推断来源。

### 3. Core investment metric cards

五项现有核心指标继续保持卡片布局，差异信息直接放入每个指标卡，不在卡片下方另起一组文本。

指标：

- 项目全投资 IRR
- 全投资静态回收期
- 资本金 IRR
- 资本金静态回收期
- 年均利润

每项显示当前版本主值，以及相对比较版本的趋势信息：

```text
项目全投资 IRR
8.42%
折线下降箭头  下降 0.86 个百分点
```

颜色按经济含义判断，不按单纯的数值增减判断：

| 指标 | 数值增加 | 数值减少 |
|---|---|---|
| 项目全投资 IRR | 绿色，变好 | 红色，变差 |
| 全投资静态回收期 | 红色，变差 | 绿色，变好 |
| 资本金 IRR | 绿色，变好 | 红色，变差 |
| 资本金静态回收期 | 红色，变差 | 绿色，变好 |
| 年均利润 | 绿色，变好 | 红色，变差 |

箭头规则：

- 使用 Lucide 风格的折线趋势箭头，不使用 Unicode `↑`、`↓` 或直线箭头。
- 数值增加使用折线向上趋势图标。
- 数值减少使用折线向下趋势图标。
- 箭头方向表达数值变化方向，颜色表达投资表现好坏。
- 按展示精度归一化后无变化时使用中性灰色短横线，不显示趋势箭头。
- IRR 差异使用“百分点”，回收期使用“年”，年均利润使用“万元”。
- IRR 使用百分点差值，例如 `8.42% → 9.28%` 显示“增加 0.86 个百分点”。

### 4. Parameter adjustment area

参数调整区域只负责编辑当前冻结参数并生成下一版，不再展示“版本差异”或“查看全部参数”表。

建议保持原有参数调整和高级参数入口，但明确文案：

```text
调整参数并重新测算
以 V3 冻结参数为起点，修改后生成下一版本
```

交互：

- 默认收起编辑区域。
- 用户点击“调整参数”后展开现有可修改参数和高级参数编辑控件。
- 编辑区使用当前版本冻结入参作为基线。
- 提交后生成下一版本，并由新结果卡展示新的差异摘要。
- 未提交草稿不进入版本差异、右侧档案或历史快照。

### 5. Project archive

右侧项目档案继续作为版本索引和跳转入口，不提供独立比较能力。

每条测算记录保持紧凑，项目全投资 IRR 是最醒目的数字：

```text
V3                         14:32
甘肃 · 100MW / 200MWh

项目全投资 IRR
8.42%

较 V2：主动调整 2 项 · 联动更新 2 项
运营期、策略达成率等 4 项
```

右侧规则：

- 固定将 Vn 与相邻上一版 Vn-1 比较。
- 明确写出参照版本，例如“较 V2”。
- 不受主结果卡临时选择的比较版本影响。
- 不展示财务指标的版本差值，不显示趋势箭头。
- 只展示总摘要，不区分项目基本信息、可修改参数、高级参数。
- 主动调整和联动更新分别统计；没有某一类时不显示该类。
- 每个来源最多展示两个代表字段。
- 该来源不超过两项时完整列出字段名。
- 超过两项时列出前两项，并追加“等 N 项”，其中 N 是该来源的变化总数。
- 右侧卡片控制为固定或半固定紧凑高度，摘要最多占两行；字段过长使用省略号。
- V1 显示“首个测算版本”，不显示比较摘要。
- 点击卡片只定位对应对话结果，并保持主结果卡的当前访问比较选择规则。
- 右侧报告记录区域保持现有独立职责，不与测算版本摘要合并。

### 6. Responsive behavior

- 桌面端保留主结果区与右侧档案并列结构。
- 中等宽度下右侧档案按现有页面规则转为可打开的项目档案区域，记录卡不改变信息口径。
- 窄屏下五项指标卡按两列或一列重排，趋势信息保持在对应指标内部。
- 比较控件在结果横幅下方独占一行，保持可读，不让长项目识别信息挤压原生选择框。
- 差异行在窄屏下从“来源标签同一行”重排为来源标签独占辅助行，旧值、新值和折线仍保持清晰。
- 右侧记录的 IRR、版本号、项目识别信息和两行摘要不得互相遮挡。
- 所有按钮、选择框和记录卡保留键盘焦点、悬停、按下和禁用状态。

## Data flow

1. 后端保存每个成功测算的冻结输入、主动提交键、联动更新键和结果快照。
2. 会话回放接口返回版本列表、版本输入快照、结果快照和来源元数据。
3. 前端按当前版本和用户选择的比较版本生成主结果卡差异视图；后端提供的来源分类优先于前端推断。
4. 前端按相邻版本生成右侧固定摘要，忽略主卡当前临时比较选择。
5. 前端在 Pinia 会话状态中保存 `comparisonVersionByVersion`，刷新或重新打开会话时丢弃该临时状态。

建议前端版本对象增加：

```js
{
  taskId,
  version,
  result,
  input,
  calculatedAt,
  changeMeta: {
    previousTaskId,
    explicitOverrideKeys,
    derivedChangedKeys,
  }
}
```

## Edge cases

- V1 没有比较对象：显示首个测算版本状态，核心指标不显示差异行。
- 比较版本缺少某个参数：差异行旧值显示“—”，并标记为新增或无法回溯，不能把缺失当成数值 0。
- 当前版本与比较版本最终入参完全一致：显示参数未变化；指标若也无有效差异则显示中性状态。
- 主动提交值被依赖规则忽略：不计入最终主动调整，来源应由后端根据最终生效结果记录。
- 系统联动变化很多：主卡完整展示；右侧摘要只显示每个来源前两个字段和总数。
- 同一会话内版本任务失败：失败任务不作为成功版本比较对象，也不生成右侧成功测算记录。
- 版本或参数名称过长：主卡允许换行；右侧摘要截断，保留总数和参照版本。
- 结果指标缺失：显示“—”，不生成趋势箭头，也不计算颜色。
- 数值格式化后的差异为零：显示中性灰色，不误报变化。

## Acceptance criteria

- V3 默认显示“对比 V2”；切换到 V1 后，参数差异和五项指标差异同步切换。
- 当前访问期间从 V3 切换到其他版本再返回 V3，恢复 V3 最近选择的比较版本。
- 刷新或重新打开会话后，V3 恢复与 V2 比较。
- 主结果卡能按项目基本信息、可修改参数、高级参数分别展示变化字段。
- 每条变化字段能正确标记主动调整或联动更新，且来源不由前端猜测。
- IRR 和利润增加显示绿色折线上升趋势；IRR 和利润减少显示红色折线下降趋势。
- 回收期增加显示红色折线上升趋势；回收期减少显示绿色折线下降趋势。
- 五项指标持平时显示中性状态，不显示趋势箭头。
- 环形图和现金流图不出现额外比较文本。
- 右侧每条记录明确显示“较 Vn-1”，V1 显示首个测算版本。
- 右侧 IRR 仍为卡片最醒目数字，且卡片高度不因摘要字段数量明显增长。
- 右侧摘要不区分类别，只分别总结主动调整和联动更新；每类最多显示两个字段。
- 点击右侧记录只定位对话中的对应结果，不打开额外差异抽屉、不改变右侧固定比较口径。
- 桌面与窄屏下不出现横向滚动、文本遮挡或不可用的选择控件。

## Implementation boundaries

预期涉及的生产文件由实现计划进一步确认，初步范围包括：

- 前端结果卡和核心指标组件。
- 前端计算 Pinia store 的版本对象和当前访问比较选择状态。
- 前端首页右侧项目档案模板及其样式。
- 后端输入快照/任务响应的数据契约和来源元数据生成。
- 对应的前端单元测试、后端快照/接口测试和响应式验证。

不删除现有生产文件，不自动执行 Git 操作，不改变无关模块。
