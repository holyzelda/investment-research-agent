# 登录图形选择验证码需求与设计

## 1. 背景与问题

当前独立登录页从 `/gateway/code` 获取验证码，用户输入图片中的短字符后，将 `code` 和 `uuid` 与账号、密码一起提交给 ecenter 登录接口。字符验证码的答案空间小，容易被 OCR、重放和自动化撞库绕过；刷新、加载失败和输错后的反馈也只有通用提示。

本需求将字符输入验证码升级为**图形选择验证码**：用户根据题目在图片网格中选择符合条件的图片，服务端校验成功后签发一次性验证凭证，再使用该凭证登录。验证码的生成、答案和校验均属于统一平台/ecenter 的认证安全边界；本应用只负责展示挑战、收集选择和传递平台签发的凭证，不在浏览器中保存答案或自行判定正误。

## 2. 目标

- 提高自动化脚本、OCR 和简单重放攻击完成登录的成本。
- 在桌面端和窄屏环境提供明确、可恢复、可键盘操作的选择流程。
- 验证码答案不下发到前端，图片地址不暴露对象语义，验证凭证只能使用一次且短时有效。
- 保持账号密码、Token、用户信息与动态菜单的既有登录流程不变。
- 支持灰度、监控和紧急回退；新接口异常时不得静默降低为无验证码登录。
- 为无法完成视觉题目的用户提供等强度的无障碍替代挑战。

## 3. 非目标

- 不在 IR 后端实现验证码生成、图片素材管理、答案判定或登录认证。
- 不改变注册、找回密码、用户管理、RBAC、Token 签发与刷新逻辑。
- 不承诺通过增加图片数量彻底阻止机器识别；验证码只是登录风控的一层。
- 首期不实现拖拽拼图、轨迹识别或第三方验证码供应商绑定。
- 不允许前端在新接口失败时继续提交账号密码，或回退为客户端可验证的固定答案。

## 4. 术语和角色

- **挑战（challenge）**：一次由平台创建的验证码会话，包含题目、图片网格和到期时间。
- **选项（tile）**：网格中的一张可选择图片；前端只知道无语义的 `tileId`。
- **挑战 ID（challengeId）**：服务端生成的随机、不透明标识，不包含用户或答案信息。
- **验证凭证（captchaToken）**：挑战通过后由平台签发的一次性短期凭证。
- **认证平台**：ecenter 及其可信网关，负责挑战、校验、限流、审计和登录。
- **IR 前端**：本仓库登录页，只渲染和转发认证平台数据。

## 5. 用户范围与触发策略

### 5.1 首期范围

独立登录页的账号密码登录使用图形选择验证码。已通过统一平台登录并携带有效 Token 跳转到本系统的用户不重复展示验证码。验证码是否启用继续由平台配置决定，前端不得自行按账号或环境绕开。

### 5.2 推荐风控策略

平台至少支持以下策略，并由服务端决定，前端只消费结果：

1. 默认在提交账号密码前完成一次挑战。
2. 同一账号、IP 或设备连续失败时提高挑战强度并执行登录限流。
3. 挑战校验失败不计为密码错误；密码错误仍按现有账号安全策略计数。
4. 挑战创建、校验和登录均采用独立限流桶，防止攻击者利用刷新大量消耗素材和计算资源。
5. 平台关闭验证码时返回 `captchaEnabled: false`；只有明确的服务端配置可以关闭，网络错误不能视为关闭。

## 6. 用户流程

### 6.1 正常流程

1. 登录页加载后请求一个图形挑战。
2. 页面显示题目，例如“请选择所有包含输电塔的图片”，以及 3×3 图片网格。
3. 用户点击图片；选中项显示高对比描边、勾选图标和“已选中”的可访问状态。
4. 用户点击“验证”。前端提交 `challengeId` 和无序去重后的 `tileIds`。
5. 验证成功后平台返回一次性 `captchaToken`；界面显示“验证通过”，登录按钮可提交。
6. 用户提交账号和密码。前端只向登录接口提交账号、加密后的密码及 `captchaToken`。
7. 登录成功后清除挑战状态并进入原目标页；登录失败后清除凭证并获取新挑战。

### 6.2 状态机

```text
loading ──成功──> ready ──提交──> verifying ──通过──> verified ──登录──> consumed
   │                 │                │                    │
   └─失败─> loadError│                └─失败/过期─> ready*  └─登录失败─> loading
                     └─刷新/过期──────────────────> loading

* 平台可返回替换后的完整挑战；若没有替换挑战，前端重新创建。
```

任何时刻最多保留一个活动挑战。新建或刷新挑战后，旧 `challengeId`、选择集合和 `captchaToken` 必须立即作废并从前端状态清除。

### 6.3 异常和恢复

| 场景 | 用户反馈 | 恢复方式 |
| --- | --- | --- |
| 挑战加载中 | 网格骨架屏；验证和登录按钮禁用 | 请求完成后进入可操作状态 |
| 挑战加载失败 | “验证内容加载失败，请重试” | 展示“重新加载”，不得绕过验证码 |
| 未选择图片 | “请至少选择一张图片” | 保留当前挑战 |
| 选择错误 | “选择不正确，请重试” | 清除选择；采用平台返回的新题或重新获取 |
| 挑战过期 | “验证已过期，请重新完成” | 自动加载新挑战 |
| 验证请求超时 | “验证请求超时，请重试” | 禁止自动重复提交；重新加载挑战以避免结果不确定 |
| 验证已通过后修改账号 | 验证状态失效 | 清除凭证并获取新挑战，防止跨账号复用 |
| 登录失败 | 展示平台的安全化错误文案 | 清除凭证并获取新挑战；不保留密码 |
| 图片部分加载失败 | 标记加载失败 | 整题作废并提供刷新，不允许在残缺网格上验证 |

## 7. 界面与交互设计

### 7.0 可评审交互原型

本设计附带一个无构建依赖的[高保真交互原型](../prototypes/graphical-selection-captcha.html)，可直接用浏览器打开。原型用于在研发前共同确认信息层级、视觉反馈和操作节奏，不作为生产代码或平台素材：

- 可点击图片完成多选/取消，观察描边、勾选和选择数量三重反馈。
- “验证”仅在至少选中一项后可用；验证中避免重复提交，通过后网格折叠且焦点进入登录按钮。
- “刷新”“重新验证”“换一个验证方式”和验证后修改账号均提供可操作的状态演示。
- 桌面端呈现品牌区与登录区双栏布局，820 px 以下收敛为单栏，供 360 px 窄屏走查。
- 原型使用内嵌合成插画且模拟验证必定成功；不包含真实答案判定、网络请求、倒计时和登录行为。

评审时按以下路径操作并记录问题：

1. **首次进入**：确认题目、九宫格与主操作的视觉顺序，未选择时“验证”和“登录”均不可用。
2. **选择与反选**：鼠标及键盘各操作一次，确认焦点、选中态与数量播报清晰。
3. **刷新与替代方式**：刷新后旧选择归零且焦点回到题目；替代方式提示不会绕过验证。
4. **验证通过**：网格折叠为紧凑成功态，登录按钮启用且获得焦点；“重新验证”可撤销凭证。
5. **账号变更**：验证后编辑账号，成功态立即失效，并提示需要重新验证。
6. **窄屏走查**：在 360×800 视口确认无横向滚动、图片目标尺寸合规且操作按钮不重叠。

> 原型中的固定场景类别只存在于评审文件中。生产组件不得内置题库、正确项或此处的 SVG，必须渲染平台返回的无语义图片地址。

#### 截图环境

仓库提供隔离的 Playwright 截图环境，不要求宿主机安装浏览器或 npm 包。宿主机安装 Docker 后，在仓库根目录运行：

```bash
./scripts/capture-prototype-screenshots.sh
```

脚本基于固定版本的 Playwright 容器构建截图工具，并输出以下评审材料：

- `docs/superpowers/prototypes/screenshots/desktop-selected.png`：1440×1000 桌面视口，展示已选择两张图片的状态。
- `docs/superpowers/prototypes/screenshots/mobile-verified.png`：360×800 窄屏视口，展示验证通过后的折叠状态。

截图固定使用 `prefers-reduced-motion: reduce`，等待目标状态实际出现后再捕获，以减少时间相关的像素差异。重新生成会覆盖同名文件；评审人应以 HTML 原型作为可操作的权威版本，PNG 仅用于 PR 快速预览。
容器烟测工作流也会执行相同命令并检查两个 PNG 输出，防止浏览器版本、定位器或原型结构变化使截图环境失效。

### 7.1 布局

验证码区域位于密码框与登录按钮之间：

```text
┌──────────────────────────────┐
│ 安全验证                 刷新 │
│ 请选择所有包含输电塔的图片   │
│ ┌────┐ ┌────┐ ┌────┐        │
│ │  ✓ │ │    │ │    │        │
│ ├────┤ ├────┤ ├────┤        │
│ │    │ │  ✓ │ │    │        │
│ ├────┤ ├────┤ ├────┤        │
│ │    │ │    │ │    │        │
│ [换一个验证方式]     [验证]   │
└──────────────────────────────┘
```

- 桌面端默认 3×3；服务端可返回 2×3 至 4×4，但首期最多 9 张，以控制可用性和流量。
- 图片使用固定 1:1 容器和 `object-fit: cover`，全部加载完成后再允许选择，避免布局跳动。
- 刷新按钮需要文字和图标；加载中显示旋转状态并禁用重复点击。
- 选中态不能只依赖颜色，必须同时使用描边、勾选图标和 `aria-pressed="true"`。
- 验证通过后折叠网格，显示“安全验证已通过”和“重新验证”入口；凭证过期时自动展开新挑战。
- 窄屏保持至少 44×44 CSS px 的点击目标，网格不得水平滚动。

### 7.2 键盘和无障碍

- 网格使用语义化按钮；Tab 进入网格，方向键在图片间移动，Space/Enter 切换选择。
- 题目通过 `aria-describedby` 与网格关联；选择数量和校验结果通过 `aria-live="polite"` 播报。
- 图片 `alt` 不得透露对象类别或答案，使用“验证图片 1”等中性文本。
- 提供“换一个验证方式”，由平台返回等强度的音频或其他无障碍挑战；不得把固定短信验证码作为默认弱降级。
- 焦点在刷新后回到新题目，在校验失败后回到题目说明，在校验通过后移到登录按钮。

### 7.3 表单规则

- 账号、密码填写完整且验证码已通过时，登录按钮才可用。
- 改变账号会使已通过凭证失效；显示密码、调整窗口和路由 query 不影响凭证。
- 校验与登录提交期间均防止双击；按钮显示明确的处理中状态。
- 不把密码、选项 ID、挑战 ID 或凭证写入 URL、localStorage、sessionStorage、Pinia 持久化或日志。

### 7.4 交互细节与动效

| 触发 | 即时反馈 | 后续反馈 | 焦点处理 |
| --- | --- | --- | --- |
| 选择/取消图片 | 100 ms 内切换 3 px 描边、勾选与 `aria-pressed` | 更新“已选择 N 张图片”；选择为空时禁用“验证” | 留在当前图片，便于连续操作 |
| 点击验证 | 按钮变为“验证中…”并禁用网格、刷新及重复提交 | 成功时折叠网格；失败时清空选择并替换挑战 | 成功到登录按钮；失败到新题目 |
| 点击刷新 | 刷新图标旋转，立即禁止旧网格交互 | 新挑战完整加载后整体替换，避免逐图跳动 | 回到新题目说明 |
| 凭证过期 | 成功态切回加载态，登录按钮同步禁用 | 展示“验证已过期”，加载新挑战 | 页面可见时移到新题目；后台恢复时只播报不抢焦点 |
| 修改账号 | 立即撤销已通过状态并禁用登录 | 新挑战就绪后提示“账号已修改，请重新验证” | 保持在账号输入框，不抢夺输入焦点 |
| 点击替代方式 | 当前模式控件禁用并显示加载态 | 成功后原位替换为平台返回的替代挑战 | 移到替代挑战标题 |

- 选中反馈采用 120–160 ms 的缩放/淡入，刷新图标采用不超过 600 ms 的匀速旋转；不得使用容易误解为校验成功的弹跳或庆祝动效。
- 遵循 `prefers-reduced-motion: reduce`，关闭缩放、旋转和折叠过渡，但保留同步的文本及状态变化。
- “验证中”和“登录中”至少保留文本，加载图标仅作辅助；网络完成后不人为增加等待时间。
- 错误信息出现在题目与主操作之间并使用 `role="status"`；只有阻止继续操作的系统错误使用 `role="alert"`。
- 平台限流时，“请在 N 秒后重试”每秒更新可见文本，但屏幕阅读器只在开始和恢复可用时播报，避免连续打断。

### 7.5 页面状态原型

| 状态 | 网格 | 辅助操作 | 主按钮 | 页面登录按钮 |
| --- | --- | --- | --- | --- |
| `loading` | 9 个等比例骨架块，不显示旧图 | 刷新/替代方式禁用 | “加载中…”禁用 | 禁用 |
| `ready-empty` | 可操作，无选中项 | 可用 | “验证”禁用 | 禁用 |
| `ready-selected` | 可操作，显示选择数量 | 可用 | “验证”可用 | 禁用 |
| `verifying` | 保留选择但整体禁用 | 禁用 | “验证中…”禁用 | 禁用 |
| `incorrect` | 替换为新挑战并清空选择 | 可用 | “验证”禁用 | 禁用 |
| `loadError` | 错误占位，不显示残缺图片 | “重新加载”可用 | 隐藏 | 禁用 |
| `verified` | 折叠，显示成功图标和有效期 | “重新验证”可用 | 隐藏 | 账号密码完整时可用 |
| `rateLimited` | 保留当前题但禁止提交 | 刷新禁用 | 显示剩余秒数并禁用 | 禁用 |

加载骨架只表达布局，不显示可能被误认为可选图片的图案。错误恢复必须由用户明确触发或使用服务端返回的新挑战，不对结果未知的校验请求自动重放。

## 8. 平台接口契约

以下为推荐的 v2 契约。路径仍位于平台网关，不使用 IR 业务前缀，也不附加 IR `userId` / `username` Header。统一响应壳保持 `{code, msg, data}`。

### 8.1 创建挑战

`POST /gateway/ecenter/system/auth/captcha/challenges`

请求：

```json
{
  "scene": "password_login",
  "accountHint": "sha256-normalized-account",
  "preferredMode": "image_selection"
}
```

`accountHint` 由平台 SDK 或服务端产生时优先；若前端无法安全生成，可省略，禁止明文传账号用于预取挑战。

响应：

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "captchaEnabled": true,
    "challengeId": "opaque-random-id",
    "type": "image_selection",
    "prompt": "请选择所有包含输电塔的图片",
    "columns": 3,
    "expiresIn": 120,
    "tiles": [
      { "tileId": "t_7f...", "imageUrl": "/gateway/captcha/assets/a_9c..." }
    ],
    "alternativeModes": ["audio"]
  }
}
```

约束：

- `challengeId` 至少 128 bit 随机性，单次会话有效，默认 120 秒过期。
- 图片 URL 使用短时签名或受控代理路径，不包含文件原名、类别、答案或可预测序号。
- 返回顺序每题随机化；相同素材不得长期保持相同 `tileId`。
- `captchaEnabled: false` 时不返回挑战内容；前端保留现有无验证码登录兼容能力。

### 8.2 校验选择

`POST /gateway/ecenter/system/auth/captcha/challenges/{challengeId}/verify`

请求：

```json
{
  "tileIds": ["t_7f...", "t_a2..."]
}
```

成功响应：

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "verified": true,
    "captchaToken": "opaque-one-time-token",
    "expiresIn": 120
  }
}
```

失败响应使用稳定业务码，并可在 `data.nextChallenge` 中直接携带与创建接口同结构的新挑战，减少一次往返：

| 业务码 | 含义 | 前端处理 |
| --- | --- | --- |
| `CAPTCHA_INCORRECT` | 选择不正确 | 提示后使用新挑战 |
| `CAPTCHA_EXPIRED` | 挑战过期 | 自动创建新挑战 |
| `CAPTCHA_CONSUMED` | 挑战已使用 | 自动创建新挑战 |
| `CAPTCHA_RATE_LIMITED` | 操作过于频繁 | 展示服务端 `retryAfter` 倒计时 |
| `CAPTCHA_UNAVAILABLE` | 服务暂不可用 | 保持登录不可用并允许重试 |

平台错误文案不得泄露正确图片数量、漏选/多选情况或具体正确项。

### 8.3 登录

现有 `POST /gateway/ecenter/system/auth/login` 的验证码字段演进为：

```json
{
  "username": "user",
  "password": "encrypted-password",
  "captchaToken": "opaque-one-time-token"
}
```

- 图形选择模式不再提交 `code`、`uuid` 或 `tileIds`。
- `captchaToken` 必须绑定登录场景、挑战上下文及必要的风控上下文，只能消费一次，登录成功或失败后均失效。
- 平台迁移期同时接受旧 `code + uuid` 和新 `captchaToken`，由创建挑战响应的 `type` 决定前端渲染和提交格式；迁移完成后再移除旧字段。
- 对挑战无效、过期和已使用返回稳定业务码，前端统一重置挑战，避免将其显示成“账号或密码错误”。

## 9. 安全与隐私设计

### 9.1 服务端必须保证

- 答案只存在于服务端，响应、资源元数据、文件名、缓存键和图片 EXIF 均不得泄露答案。
- 创建、刷新、校验、登录接口按 IP、账号风险标识、设备和挑战维度组合限流；网关真实 IP 只信任受控代理头。
- 挑战校验采用原子消费和常量时间敏感值比较，防止并发重复验证及明显时序侧信道。
- `captchaToken` 使用服务端存储的不透明随机值，或使用带 `jti` 且可原子核销的签名值；仅签名而无法核销不满足一次性要求。
- 图片素材经过安全审核和授权，不含个人敏感信息、攻击性内容或可执行格式；统一转码并移除元数据。
- 挑战响应设置适当的 `Cache-Control`，禁止共享缓存复用个性化挑战；全链路 HTTPS。
- 记录审计事件但不记录密码、答案、完整图片 URL、选项集合或完整凭证。

### 9.2 前端必须保证

- 图片 URL 仅作为 `<img src>` 使用，不进行 canvas 像素处理或客户端答案推断。
- 组件卸载、刷新挑战、账号改变、登录结束和退出登录时清除全部挑战内存状态。
- 平台接口保持 `isToken: false` 的现有认证边界，不携带 IR 固定身份 Header。
- 使用平台返回的安全化错误类型映射本地文案，不直接展示堆栈或原始网络错误体。
- CSP 的 `img-src` 只增加明确的平台资源域，不允许通配第三方域或 `data:` 作为新挑战的长期传输方案。

## 10. 前端组件与状态设计

建议把验证码从登录页拆为 `GraphicalCaptcha.vue`，通过事件与表单解耦：

```text
props:  scene, accountRevision
emits: verified({ captchaToken, expiresAt }), invalidated(reason)
expose: reset()
```

内部状态：

```js
{
  status: 'loading' | 'ready' | 'verifying' | 'verified' | 'loadError',
  challenge: null,
  selectedTileIds: new Set(),
  captchaToken: '',
  tokenExpiresAt: 0,
  retryAfter: 0,
}
```

实现约束：

- API 模块负责适配统一响应壳和旧/新契约；组件不直接调用通用 request。
- 登录表单只持有组件签发给父级的 `captchaToken`，不读取组件答案。
- 使用递增 request version 或 AbortController，确保旧的创建/校验响应不能覆盖刷新后的挑战。
- 到期计时以绝对 `expiresAt` 判断，页面切后台后恢复时立即重新校验，不依赖定时器精度。
- 单元测试使用合成图片 URL 和假凭证，禁止依赖真实平台或真实素材。

## 11. 可观测性

平台按分钟和版本监控以下指标，不包含用户名等高基数标签：

- 挑战创建成功率、P50/P95 延迟和限流率。
- 图片完整加载率及挑战刷新率。
- 校验通过率、平均尝试次数、过期率和无障碍替代方式使用率。
- 从挑战展示到验证通过、从验证通过到登录提交的耗时。
- 验证通过后的登录成功率，以及按安全化失败类型聚合的异常变化。
- 单一挑战重复提交、单 IP 大量创建和素材异常命中等安全告警。

前端只上报随机请求追踪 ID、挑战类型、状态、耗时和错误类别；不得上报 `challengeId`、`tileId`、图片 URL、账号、密码或 `captchaToken`。

## 12. 灰度、兼容与回退

1. 平台先发布新接口和登录接口双协议支持，旧 `/gateway/code` 保持可用。
2. 前端发布双渲染能力：按服务端 `type` 选择字符验证码或图形选择验证码。
3. 内部测试账号灰度 5%，验证无障碍、接口容量和误拒率；再依次扩大到 25%、50%、100%。
4. 每阶段至少观察一个完整业务高峰，并核对登录成功率、P95 延迟、刷新率和客服反馈。
5. 紧急回退由平台配置将挑战类型切回旧字符验证码，而不是关闭验证码；前端发布物无需回滚。
6. 100% 稳定运行并完成审计后，另开任务移除旧字符验证码代码和 `/gateway/code` 依赖。

## 13. 验收标准

### 13.1 功能

- **Given** 平台启用图形选择验证码，**When** 登录页加载，**Then** 展示服务端题目和完整图片网格，不再显示字符输入框。
- **Given** 用户未选择图片，**When** 点击验证，**Then** 不发请求并提示至少选择一张。
- **Given** 选择错误、挑战过期或已消费，**When** 平台拒绝校验，**Then** 旧选择和凭证被清除，并展示可用的新挑战。
- **Given** 校验成功，**When** 用户登录，**Then** 登录请求只携带一次性 `captchaToken`，不携带 `tileIds`、`code` 或 `uuid`。
- **Given** 用户在验证后改变账号或登录失败，**Then** 原凭证立即失效且必须完成新挑战。
- **Given** 挑战服务异常，**Then** 登录保持不可提交，并提供明确的重试入口，不静默跳过验证。
- **Given** 平台明确返回 `captchaEnabled: false`，**Then** 前端按现有无验证码流程登录。
- **Given** 平台返回旧字符挑战，**Then** 迁移期前端仍可完成旧流程。

### 13.2 安全

- 浏览器网络响应和静态资源元数据中找不到答案或对象类别。
- 相同挑战凭证并发提交两次时最多一次可进入密码校验流程。
- 已过期、已使用、不同场景或被篡改的凭证均被平台拒绝。
- 日志、监控、URL、Web Storage 和错误上报中均无密码、答案、完整选择集合或完整凭证。
- 自动化验证覆盖创建/校验/登录限流，以及刷新使旧挑战失效的场景。

### 13.3 可用性与无障碍

- 仅用键盘可以加载、选择、取消选择、验证、刷新并切换替代挑战。
- 屏幕阅读器能获知题目、当前位置、选中状态、选择数量和校验结果，且图片替代文本不泄露答案。
- 360 CSS px 宽度下无横向滚动、遮挡或小于 44×44 CSS px 的图片点击目标。
- 慢网、图片加载失败、重复点击、切后台跨过有效期等场景均能恢复。

### 13.4 测试范围

- API 契约测试：新旧挑战响应、稳定业务码、登录字段和响应壳。
- 组件测试：状态机、竞态保护、凭证过期、账号改变、键盘交互和可访问属性。
- 登录集成测试：挑战通过、失败、刷新、登录失败重置和服务关闭验证码。
- 平台安全测试：重放、并发核销、越权资源获取、枚举、限流、缓存和日志脱敏。
- 人工验收：桌面/窄屏、主流浏览器、屏幕阅读器、键盘和高对比模式。

## 14. 交付拆分与责任边界

### 阶段 A：认证平台（前置）

- 挑战生成、素材服务、答案校验、一次性凭证、限流、审计和无障碍替代挑战。
- 新接口契约及登录接口双协议兼容。
- 容量评估、安全测试、监控看板和灰度开关。

### 阶段 B：IR 前端

- 新增验证码 API 适配层和 `GraphicalCaptcha` 组件。
- 登录页接入、账号变化失效、登录请求字段切换及旧协议兼容。
- 组件、API、登录流程测试和响应式/无障碍验收。

### 阶段 C：联调与灰度

- 使用隔离测试环境和合成账号完成契约联调。
- 执行安全、容量、故障恢复和回退演练。
- 按灰度指标逐级放量；达到退出条件后清理旧协议。

## 15. 上线门槛

正式放量前必须同时满足：平台接口契约冻结；一次性核销和限流安全测试通过；替代挑战可用；前端键盘和窄屏验收通过；监控与告警就绪；回退到旧字符验证码的开关完成演练。任何一项未满足都只允许在隔离环境联调，不得面向全部用户启用。
