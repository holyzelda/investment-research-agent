# 政策与市场模块设计

**日期：** 2026-07-23

## 目标与范围

补齐朱雀投研智能体的“政策与市场”前端模块。该模块为独立工作台，提供政策与市场咨询、历史咨询查看、市场资讯浏览和咨询统计筛选。

本期仅交付前端可交互闭环，咨询问答、市场资讯和统计数据均为模拟数据。后续服务端接入后，所有内容从数据库查询，并通过既定 API 模块提供给前端。本期不实现数据库、后端接口、政策检索、资讯采集或大模型调用。

本期包含：

- 新增“政策与市场”路由并启用导航入口。
- 左侧“我的提问”历史列表、新建提问与历史查看。
- 中部咨询输入、快捷问题、占位提交、加载状态与回答结果。
- 右侧市场脉搏、三项筛选统计、资讯列表、资讯详情弹窗和当日市场观察。

本期不包含删除咨询记录、历史持久化、独立主题切换、图表、真实接口、后端和数据库改动。

## 页面结构与路由

新增 `/policy-market` 路由，路由名为 `PolicyMarket`。该页与联络线地图一致，使用 `collapseSidebar: true` 隐藏通用的首页测算会话侧栏，避免其与模块内“我的提问”列表重复。

页面整体沿用应用现有顶栏、左侧模块导航轨道和 XC 深色设计体系。导航轨道中的“政策与市场”入口由禁用改为可访问，并指向 `/policy-market`。

模块内部采用三栏布局：

- 左栏：固定宽度约 248px，展示“我的提问”、新建提问动作及咨询历史列表。
- 中栏：自适应主工作区，展示页面标题、说明、咨询输入、快捷问题和回答内容。
- 右栏：固定宽度约 336px，展示市场脉搏、筛选统计、资讯和市场观察。

窄屏下三栏按内容优先级纵向堆叠，保留新建提问、输入咨询、查看当前回答与资讯详情的能力。页面内部区域独立滚动，避免顶栏与导航轨道滚出视口。

## 视觉规范

页面保持联络线地图模块的深色工作台风格：背景、表面、文字、边框、强调、语义和市场涨跌颜色均使用 `var(--xc-*)` Token。不得引入参考设计中的外部字体、独立浅色主题或硬编码颜色。

中栏以信息密度和阅读效率为先：标题、引导语、输入区和回答区采用明确的层级与留白。回答结果使用内容面板而非营销式大卡片；请求中的状态使用紧凑加载提示。

右栏包含市场脉搏标题、统计筛选、资讯提示条、资讯列表和当日观察。数值使用现有 `.xc-num` 规范；市场趋势根据中国市场惯例使用既有涨跌 Token。资讯详情使用 Element Plus 弹窗展示，不自行实现对话框。

## 前端职责划分

新增 `src/api/policyMarket.js`，作为政策与市场数据访问的唯一入口。模块预留并实现异步模拟版本的以下方法：

- `getConsultations()`：获取咨询历史。
- `submitConsultation(payload)`：提交咨询并返回占位回答。
- `getMarketNews()`：获取市场资讯列表。
- `getConsultationStats(filters)`：按筛选条件获取咨询统计。

新增 `src/store/modules/policyMarket.js`，承载页面业务状态和 API 调用。Store 负责：

- 咨询历史、当前选中咨询和初始加载状态。
- 咨询提交状态与提交失败信息。
- 市场资讯及资讯加载状态。
- 省份、时间范围、主题三个筛选条件与统计结果。
- 新建咨询、选择历史咨询、提交咨询、加载资讯和更新筛选条件的动作。

视图和子组件不得直接定义或变更业务模拟数据，不得直接调用模拟实现。后续接入数据库时，只替换 API 模块内的请求和响应映射；Store、组件层级与用户交互保持稳定。

页面按职责拆分为：页面编排、咨询历史、咨询输入、咨询结果、市场脉搏和资讯详情组件。组件通过 props、emit 与 Store 公开状态交互，不跨组件直接修改状态。

## 数据模型与后续接口契约

模拟数据字段须贴近后续数据库 DTO，避免接入时变更页面模型。

咨询记录：

```js
{
  id: 'consultation-001',
  title: '新能源消纳政策有何变化？',
  question: '新能源消纳政策有何变化？',
  answer: '...',
  status: 'completed',
  createdAt: '2026-07-23T10:42:00+08:00',
  sourceScope: ['政策文件', '市场行情', '行业资讯']
}
```

市场资讯：

```js
{
  id: 'news-001',
  category: '政策',
  title: '国家能源局：加快推动新型储能规模化发展',
  publishedAt: '2026-07-23T09:00:00+08:00',
  content: '...',
  source: '政策与市场研究台公开信息整理'
}
```

统计查询参数：

```js
{
  province: 'all',
  period: 'all',
  topic: 'all'
}
```

统计结果：

```js
{
  total: 0,
  trend: 0,
  rangeLabel: '全部省份'
}
```

当前模拟实现可在 API 模块内根据统计明细聚合返回该结果；真实后端接入后由数据库查询聚合，前端仅透传筛选参数并消费结果。

## 交互流程

进入页面时，Store 并行加载咨询列表、资讯和默认统计。加载失败时显示轻量错误状态，并保留其他已成功加载的数据。

用户点击“新建提问”后，清空当前选中咨询，结果区回到空状态，并聚焦咨询输入框。左栏不提供删除操作。

用户点击任意历史记录后，中栏展示对应问题、回答、检索范围和状态。快捷问题仅将文本填入输入框，不自动提交。

用户提交非空问题时：

1. 将问题作为当前咨询置入处理中状态。
2. 显示“正在分析”加载状态。
3. 调用 `submitConsultation`。
4. 成功后用返回的结构化回答更新该记录，并刷新左侧选择态。
5. 失败后显示失败提示并允许用户重新提交，不伪造成功回答。

空输入不发起请求，输入框获得焦点。支持 `Ctrl/Cmd + Enter` 提交。

右侧三个筛选项为省份、时间范围和咨询主题。任意筛选变化后调用 `getConsultationStats(filters)`，并更新咨询总数、范围标签及趋势文案。资讯条目可点击，使用详情弹窗展示分类、标题、日期、正文和来源。

## 错误处理与可访问性

所有异步动作必须明确管理 `loading` 与 `error` 状态。请求失败时使用现有 Element Plus 消息提示或与页面一致的内联错误提示；不得清空此前成功加载的数据，也不得将错误伪装为“暂无数据”。

交互元素使用原生按钮或 Element Plus 控件，并提供可识别的 `aria-label`。键盘用户可完成新建、选择历史、输入、提交、筛选、打开和关闭资讯详情。焦点可见状态复用 XC 强调色。

## 测试与验收

新增或更新 Vitest 测试，至少覆盖：

- 政策与市场路由存在，导航入口可点击，页面隐藏通用测算会话侧栏。
- 初始数据加载及模拟 API 失败状态。
- 新建提问清空当前结果，历史咨询切换后正确展示回答。
- 快捷问题填入输入框，空输入阻止提交，`Ctrl/Cmd + Enter` 可提交。
- 提交过程中展示加载状态，成功后更新结果，失败后显示错误且不产生伪造回答。
- 三项统计筛选正确传递参数并更新统计结果。
- 点击资讯可打开详情弹窗并展示正文和来源。

验收标准：页面在现有前端项目中可通过路由访问；视觉 Token 和导航行为与联络线地图一致；所有内容均通过 API 占位层和 Store 进入组件；本期不包含任何后端、数据库或真实问答服务改动。
