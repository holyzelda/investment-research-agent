# 正式报告模块设计

## 目标

用户对已完成的测算版本发起“生成报告”后，系统以该测算任务的冻结快照为唯一数据源，生成一份不可修改、可恢复的正式报告。报告在独立前端页面等价呈现 DOCX 模板的内容和图表，并允许用户通过浏览器打印功能保存报告正文为 PDF。

## 范围

本设计实现：

- 每个已完成测算任务生成零或一份正式报告；
- 异步报告生成、SSE 步骤进度与 AI 章节重试；
- 报告完整 JSON 快照、会话时间线事件和右侧报告记录；
- 报告详情页 `/reports/:reportId`；
- DOCX 模板的规则化章节、图表和 AI 章节；
- 浏览器打印为 PDF。

本设计不实现：

- DOCX 生成、DOCX 在线预览或 DOCX 转换；
- 后端 PDF 渲染、Playwright/Chromium、PDF 接口、PDF 持久化或对象存储；
- 报告编辑、重生成、报告版本、报告删除；
- 任务队列、Worker、服务重启后的自动续跑；
- 用户输入中未出现的报告资料追问或补填。

## 领域模型

- **测算任务**：一个冻结的测算版本，拥有入参、取数、飞书 I/O 与测算结果快照。
- **正式报告**：用户从一个已完成测算任务主动创建的不可变档案。一个测算任务最多对应一份正式报告。
- **报告生成任务**：生成过程的短期状态载体；不是正式报告内容，状态仅为 `generating`、`completed`、`failed`。
- **正式报告快照**：正式报告唯一持久化内容，保存完整 JSON payload。详情页和打印页面只读该快照。

关系：

```text
Conversation
└─ Calculation task (Vn)
   ├─ frozen calculation snapshots
   ├─ zero or one report-generation task at a time
   └─ zero or one immutable formal report
```

## 生成与不可变性

1. 只有当前用户拥有、所属会话未软删除、且状态为 `completed` 的测算任务可以发起报告生成。
2. 报告生成先构建规则化报告内容，再生成 AI 章节，最后原子写入正式报告快照与报告生成时间线事件。
3. 正式报告创建成功后，不允许编辑、补写、重生成或创建第二份。
4. AI 章节独立最多尝试 3 次；连续失败时，报告仍成功创建，章节冻结为：

   > 本节智能分析暂未生成，不影响测算数据、图表及规则化内容的展示。

5. 仅规则化主体构建、正式报告快照写入或时间线事件写入失败时，生成任务整体标为 `failed`，且不得创建正式报告。
6. 服务启动时，将所有遗留 `generating` 报告生成任务直接置为 `failed`；首版不恢复执行。
7. 同一任务的生成中重复请求返回现有生成任务；已有正式报告时返回既有报告。正式报告表的 `UNIQUE(task_id)` 是最终约束。

## 报告数据冻结

报告不得在生成或查看时读取飞书副本、本地 XLSX、实时外部数据或当前测算数据。测算完成时，除现有结果快照外，必须将报告所需数据冻结进任务的快照数据。

### 飞书省份资料

读取配置中 `revenue_structure_token` 指向的飞书工作簿，不读取本地 XLSX：

| 报告章节 | 飞书 sheet | 冻结规则 |
|---|---|---|
| 1.2 市场供需分析 | `各省能源结构` | 仅冻结并展示该省存在的字段；没有的字段不展示。 |
| 2.1 市场状态 | `各省电力市场情况` | `1` 为“已启动”；`0` 或空值为“未启动”。 |
| 2.1 对项目影响 | `各省收益结构` | 使用既有测算市场开关；`1` 为“纳入测算”；`0` 或空值为“不纳入测算”。 |

报告专用飞书资料读取失败不阻断测算：测算仍完成，相关资料记录为不可用或空；报告 1.2 隐藏无资料内容，2.1 按空值映射规则展示。

### 图表序列

按冻结的 `operation_years` 读取并保存飞书 `画图数据`：

| 数据 | 15 年范围 | 20 年范围 |
|---|---|---|
| 现金流口径偿债覆盖倍数 | `C3:Q3` | `C3:V3` |
| 偿债后自由现金流 | `C6:Q6` | `C6:V6` |
| 经营性现金流 | `C7:Q7` | `C7:V7` |
| 还本 | `C8:Q8` | `C8:V8` |
| 付息 | `C9:Q9` | `C9:V9` |
| 净利润 | `C11:Q11` | `C11:V11` |
| 折旧摊销 | `C12:Q12` | `C12:V12` |
| 基准/乐观/悲观平均偿债覆盖倍数 | `B27` / `B29` / `B31` | `B27` / `B29` / `B31` |

历史旧记录不做兼容。本模块实施时可在用户另次确认完整 SQL 后，删除测试环境现有测算/快照记录并使用新结构重建。

## 模板映射与内容规则

源模板：`D:\0_工作\2026\投研智能体\报告模块\储能项目测算方案_模板_v1.1.docx`。

DOCX 仅是章节、内容和版式参考，不作为线上模板或输出格式。模板现有的章节编号/名称缺陷按原样呈现，不自动更正。

### 项目基础资料

- 报告名称、事件卡标题、右侧报告卡、详情标题和打印文件默认名：`{省份}{功率}MW/{容量}MWh储能项目测算方案`。
- 当前不从自由文本提取自定义项目名称。
- 编制单位固定为“西安奇点能源股份有限公司”。
- 编制日期为报告生成日，格式 `YYYY-MM-DD`。
- 项目类型固定“源网侧”。
- 奇点能源定位固定“设备商+运营商”。
- 有节点时展示节点；没有节点时展示省份。
- 储能时长为容量除以功率。
- 业主单位、预期投运时间和业主背景没有来自首次输入的信息时留空，不追问。

### 规则化与 AI 内容

- 有批注明确数据来源或计算规则的章节，按冻结数据确定性生成。
- 模板批注和第 6.4 节既有 AI 提示词是 AI 内容唯一业务约束。
- 实现必须结构化固化各 AI 章节的输入范围、字数、分析视角、禁止使用的指标、文风、结论要求及缺数规则；不得自行新增阈值或改写判断口径。
- 关键数据缺失时，AI 内容使用：`需补充核实：____`。
- 当前以独立报告 AI 生成端口调用；先用确定性假实现支持成功和失败重试测试。未来中台提供“提示词输入、文本输出”API 后，仅替换基础设施适配器，不改变报告契约。

## 持久化

### 正式报告快照

既有 `ir_report_snapshot` 作为正式报告表，保存一份完整不可变 JSON payload。除既有 `report_id`、`task_id`、`conversation_id`、`user_id`、`schema_version`、`payload` 外，payload 至少包含：

- 名称、生成日期、来源 `taskId` 与测算版本；
- 项目基本信息；
- 冻结的省份能源资料和市场/收益映射；
- 现货价费、测算边界、财务指标、收益结构；
- 图表原始序列和展示所需配置；
- 每一 AI 章节的文本、状态、重试次数、降级文案标识；
- 模板提示词/规则版本和报告结构版本。

### 报告生成任务

新增轻量报告生成任务表，至少关联 `task_id`、`conversation_id`、`user_id`，保存状态、步骤列表/当前步骤、错误信息和创建时间。其用途仅为生成过程、SSE 恢复和失败重试；成功后正式内容只读 `ir_report_snapshot`。

### 时间线与会话详情

正式报告创建成功后追加一条消息快照：

```json
{
  "message_type": "report_generated",
  "content": "报告已生成",
  "payload": {
    "event_type": "report_generated",
    "report_id": "…",
    "task_id": 123
  }
}
```

会话详情扩展：

- `reports`：本会话报告卡列表，包含 `reportId`、名称、`taskId`、`version` 和生成时间；
- `messages`：返回报告生成事件；
- `versions`：返回报告摘要或空值，供结果卡决定生成按钮状态。

## 接口

所有 JSON 接口保持 `{code, msg, data}` 响应壳。

| 接口 | 行为 |
|---|---|
| `POST /ir/calc/tasks/{taskId}/report` | 创建或复用报告生成任务；已有正式报告则返回既有报告。 |
| `GET /ir/report-tasks/{reportTaskId}` | 返回状态、步骤、当前步骤、耗时、错误和成功后的 `reportId`。 |
| `GET /ir/report-tasks/{reportTaskId}/events` | SSE 推送生成步骤和状态变化。断线后前端通过状态接口恢复。 |
| `GET /ir/reports/{reportId}` | 返回完整正式报告快照。 |

所有报告资源读取均按当前用户、关联任务、所属会话和会话未软删除校验；不满足统一为 404。

不提供后端 PDF 接口。

## 前端交互

### 首页

- 结果卡中按钮状态：`生成报告` → `报告生成中`（置灰） → `已生成报告`（查看入口）；整体失败且未生成正式报告时显示 `重新生成报告`。
- 生成中展示步骤进度链：启动占位、当前节点转圈、已完成打钩、AI 章节的第 N/3 次重试、总耗时；完成后允许折叠。
- 步骤链只显示可审计的业务进度，不显示原始提示词、模型隐藏推理或原始思维链。
- 成功后对话时间线追加报告已生成事件卡。
- 右侧栏分为“测算记录”和“报告记录”两个独立可滚动区域。报告卡显示名称、`关联测算：Vn`、生成时间和查看入口；无报告时显示明确空状态。
- 测算结果卡显示已生成报告入口；报告卡、详情页和结果卡均展示唯一来源版本 `Vn`。从报告详情点击版本应回到该会话并定位对应结果卡。

### 报告详情

- 独立路由：`/reports/:reportId`。
- 使用正式报告快照原生渲染完整报告页面；不读取飞书或当前测算数据。
- 报告正文根容器为 `.ir-report-document`。
- 操作区、导航、会话历史、测算版本和右侧卡片均不是报告正文。

### PDF 下载

- “下载 PDF”调用浏览器打印/保存 PDF。
- `@media print` 仅输出 `.ir-report-document`。
- 打印 CSS 固定 A4 纵向，上/下 1 英寸、左/右 1.25 英寸边距。
- 不保存 PDF 文件，不引入 PDF 依赖。分页可随浏览器略有差异，但打印内容与范围固定。

## 测试与验证

后端测试覆盖：

- 新测算冻结所有报告所需资料、市场映射与图表序列；
- 报告资料飞书读取失败不阻断测算；
- 生成幂等性、任务状态、服务重启遗留任务失败；
- AI 成功、每章三次失败后降级、整体失败后的重新生成；
- 报告快照不可变且每任务最多一份；
- SSE 步骤顺序与状态；
- 会话详情报告卡、时间线事件和版本摘要；
- 跨用户与软删除会话报告资源统一 404。

前端测试覆盖：

- 结果卡生成按钮状态和禁用；
- 进度链的启动、完成、失败、重试和折叠；
- 事件卡、右侧报告列表、版本关联和两个详情入口；
- 报告详情只以快照渲染，AI 降级文案展示；
- `@media print` 隐藏报告正文外内容，打印入口调用浏览器打印。

## 部署与依赖

- 后端新增依赖只能经 `agent-backend/requirements.txt` 管理。
- 前端新增依赖只能使用 `npm install`，并同步更新 `package.json` 与 `package-lock.json`。
- 当前方案不需要 Playwright、Chromium、服务端 HTML-to-PDF 库、PDF 文件存储或 DOCX 生成依赖。
