# 省级现货预计算区域规则改造设计

## 目标

将省级预计算的源数据选择改为固定的 29 条业务规则。每条规则明确源库 `area`、源库 `mode` 和写入 `ir_agent.ir_spot_daily_optimal_province.province` 的目标省份。预计算仍支持按已写日期断点续跑；每次省级运行均覆盖完整规则清单，不再接受区域筛选参数。

## 范围

修改省级预计算相关的工具入口、预计算服务、源数据仓储及配置模型。

- 省级预计算只计算固定清单中的 29 个源 `area`。
- `蒙西-全网` 从 `mode=实时` 读取，写入目标 `province=蒙西`。
- `江苏-全网` 从 `mode=日前` 读取，写入目标 `province=江苏`。
- 其余 27 个区域从 `mode=日前` 读取，源 area 与目标 province 同名。
- 去除 `PROVINCE_AREAS` 工具参数和 `run_precompute()` 的 `province_areas` 参数。
- 去除废弃的全局 `spot_price.province_mode` 配置。

## 架构和数据流

预计算基础设施定义不可变的有序规则清单。`run_precompute()` 对清单逐条调用省级仓储，仓储针对该项 `area` 和 `mode` 过滤 `lamda_data.market_curve_points_current`。当日 DP 结果写入时，唯一标识使用规则中的目标 `province`，因此断点续跑以目标省份、K 和日期为依据。

```text
固定规则(area, mode, province)
  → ProvinceSpotRepository.fetch_daily_prices(area, mode, start, end)
  → 逐日 DP
  → ir_spot_daily_optimal_province(province=规则目标名, business_date, k, ...)
```

节点级预计算、K 值、逐日完整性校验、断点续跑及滚动窗口清理不改变。

## 错误处理

某个区域源库无数据时，保留既有逐 identifier 跳过并继续下一个区域的行为。不会因任一规则无数据而中止其他区域的预计算。

## 验证

为仓储和预计算服务补充单元测试，验证：固定清单仅包含 29 条规则；蒙西和江苏的源/目标映射正确；查询使用每条规则指定 mode；写入记录的 province 使用目标映射名；已写目标省份日期继续跳过。运行相关 pytest 测试和完整测试集。
