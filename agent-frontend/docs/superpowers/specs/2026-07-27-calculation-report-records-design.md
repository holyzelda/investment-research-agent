# 测算与报告记录侧栏设计

**日期：** 2026-07-27  
**状态：** 已确认

## 目标

优化测算页面右侧的“测算记录”和“报告记录”，在不刷新页面的前提下完整、稳定地展示新生成报告的信息，并改善窄屏与记录较多时的可用性。

## 展示与布局

- 主对话区与右栏使用自适应 Grid：`minmax(0, 1fr) minmax(240px, 20%)`。右栏目标占容器宽度的 20%，最小宽度为 240px。
- 右栏分为等高的“测算记录”和“报告记录”两个分区。每个分区采用固定标题与独立列表滚动区：标题始终可见，只有标题下的记录列表可垂直滚动。
- 测算记录在项目摘要与 IRR 之间新增“测算时间”，来自版本的 `calculatedAt`。
- 测算时间、报告创建时间统一显示为 `YYYY-MM-DD HH:mm:ss`。缺失或无效值显示 `—`，不暴露 ISO 格式中的 `T`。
- 报告记录的“查看报告”使用独立样式：较现有紧凑按钮更高，采用低对比度灰色中性视觉；测算记录中的生成/查看报告按钮维持既有样式。

## 数据与排序

- 报告列表只显示已完成且具有 `reportId` 的报告。
- 报告记录按 `createdAt` 解析后的时间降序排列；无法解析或缺失时间的记录放在最后。
- SSE 继续负责报告生成中的进度和完成消息。
- 收到报告完成事件后，前端请求当前会话详情，并只同步会话详情中的 `reports` 和每个已完成版本的 `report` 信息；不重建消息流、不修改当前选中版本或测算结果。这样以服务端会话详情为权威来源，立即补齐标题、版本、创建时间等元数据。

## 错误处理

- 会话详情同步失败时保留 SSE 已写入的完成状态与报告入口，避免生成成功的报告不可访问；下次打开会话仍会从服务端恢复完整数据。
- 时间格式化对空值与非法值容错为 `—`。

## 测试

- 首页侧栏渲染测试：测算与报告时间格式为到秒的本地文本，不包含 `T`；报告按创建时间降序；标题位于滚动列表之外；报告记录按钮带独立类。
- Store 测试：报告 SSE 完成后请求会话详情，并同步完成版本的报告元数据及报告列表，且保留现有消息流和选中版本。
