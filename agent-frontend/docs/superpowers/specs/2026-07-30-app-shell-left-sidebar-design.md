# AppShell 左侧一体化菜单设计

日期：2026-07-30  
状态：已批准，可实施

## 目标

参照用户提供的深色侧栏图片，将当前“顶部通栏品牌区 + 图标 AppRail + 历史 AppSidebar”重构为位于页面左侧的单一 AppShell。改造只调整布局、视觉层级、指定菜单展示文案和必要的导航衔接，保留现有动态路由、权限来源、历史会话数据及业务行为。

## 范围

### 范围内

- 将品牌、新建会话、动态模块菜单、历史会话和当前用户收拢到单一左栏。
- 以参考图的深色窄面板、整行选中态、青紫渐变主操作和分组标题为视觉方向。
- 桌面端提供展开和紧凑两种状态；窄屏端以抽屉承载完整菜单。
- 保留历史会话打开、更多菜单、二次确认软删除及当前会话高亮。
- 保留后端菜单驱动逻辑，并为菜单未加载时沿用现有本地导航回退。
- 统一按路由规范化三个菜单的展示：`/home` 显示“朱雀星核”并带“引擎”，`/index-map` 显示“朱雀寻龙图”并带“MAP”，`/policy-market` 显示“专业数据速查”且不带标记。
- 新建会话或打开历史会话时确保进入对话首页，以免在其他模块中更新了会话状态却看不到结果。
- 保留首页欢迎态现有五项平台指标，将其从旧顶栏迁入主内容列顶部。

### 范围外

- 不照搬参考图中未明确指定的其他菜单、数量、角标或锁定状态。
- 不实现参考图中的试用版、积分、升级按钮或订阅能力。
- 不修改菜单接口、测算接口、会话接口、权限模型或路由定义。
- 不改造首页内容、联络线地图、测算结果卡片或参数调整区。
- 不改变正式报告页的全宽阅读与打印布局；报告详情仍不显示 AppShell。
- 不新增前端依赖。

## 信息架构

展开态从上到下固定为：

1. 品牌区：现有品牌图标、产品名和英文副标题，右侧放折叠按钮。
2. 主操作：渐变“新建会话”按钮。
3. 工作台导航：分组标题和当前动态菜单项；当前路由使用整行圆角高亮。
4. 历史测算：分隔线、分组标题、可滚动历史列表和空状态。
5. 用户区：当前头像与用户名，固定在侧栏底部。

紧凑态只显示品牌标记、新建图标、菜单图标和用户头像。历史会话不在紧凑态逐条展开，点击展开控件后恢复完整侧栏。紧凑态的图标按钮都有可访问名称和悬浮提示。

## 组件结构

### `layout/index.vue`

- AppShell 成为 `ir-layout` 的第一列，主视图成为第二列。
- 删除顶部通栏品牌与用户区域，主视图从视口顶部开始。
- 欢迎态平台指标保留在主内容列顶部，不再与品牌、用户信息共享顶栏。
- 移除独立 `AppRail` 挂载，统一向 AppShell 传入动态导航数据、当前路由和历史数据。
- 保留现有新建、导航、历史打开和删除事件编排。
- 新建会话先重置 store，再导航到 `/home`；打开历史成功后导航到 `/home`。
- 普通业务路由不再完全隐藏 AppShell。需要更多画布空间的页面使用紧凑态，导航入口始终存在；正式报告详情保留无 AppShell 的全宽例外。

### `AppSidebar.vue`

- 接管原 `AppRail.vue` 的模块导航展示职责，组件继续负责历史会话展示。
- 新增 `items` 和 `active` 属性以及 `nav` 事件；组件按 `path` 为指定菜单补充展示 `label` 与可选 `meta`，输入数据和路由目标保持不变。
- 展开态采用 300px 稳定宽度，紧凑态采用约 68px 稳定宽度，状态变化不重排主内容内部结构。
- 使用现有 Lucide/后端 SVG 图标来源，不手绘新的业务图标。
- 历史列表保持单行省略；更多菜单仅在悬浮、聚焦或当前项时出现。
- 删除现有“折叠后悬浮临时展开”的复杂定时器交互，改为明确点击切换，避免抖动和误触。
- 菜单右侧标记使用弱对比、小字号、右对齐样式；紧凑态隐藏标记，只保留图标和 tooltip。

### `AppRail.vue`

- 不再由布局挂载。
- 若全仓搜索确认没有其他消费者，则删除组件和对应单元测试；否则保留文件但不参与 AppShell。

## 视觉系统

继续使用 XC tokens，不在 Vue 模板或 scoped CSS 中新增散落的十六进制颜色。

- 工作区：`--xc-surface-workspace`
- 侧栏面板：`--xc-surface-raised`
- 普通菜单：透明背景、`--xc-text-soft`
- 菜单悬浮：`--xc-surface-frosted`
- 菜单选中：中性提亮面，配合 `--xc-text-strong`；不把整个侧栏做成单一蓝紫色块
- 主操作：`--xc-grad-brand`，只在“新建会话”使用，作为唯一强视觉签名
- 分隔线与边框：`--xc-border-soft` / `--xc-border-card`
- 状态与危险操作：沿用现有 XC semantic tokens

品牌区和菜单使用现有 HarmonyOS/Noto/PingFang 字体栈。产品名、分组标题、菜单正文和辅助信息建立明确的字号与字重层级；不使用随视口宽度缩放的字体，也不使用负字距。

侧栏外轮廓保持克制：页面左侧留 12px 外边距，面板圆角不超过现有 `--xc-radius-sm`，不增加装饰性光球或大面积渐变背景。参考图中的青紫渐变只用于主操作按钮。

## 响应式行为

- `>= 1200px`：默认 300px 展开态，可手动切换为紧凑态。
- `768px–1199px`：首次进入时默认紧凑态，用户手动展开后切换页面仍保持展开。
- `< 768px`：AppShell 作为模态抽屉覆盖主内容，顶部提供菜单按钮；打开时阻止背景滚动，支持抽屉内关闭按钮、Esc 和遮罩关闭。
- 所有固定宽度、图标按钮和菜单行都有稳定尺寸，加载历史数据和切换选中态时不改变布局宽度。

## 数据与事件流

1. `layout/index.vue` 从 permission store 生成导航项，并根据当前路由计算 active key。
2. AppShell 按菜单 `path` 规范化指定展示文案与右侧标记后渲染导航；点击仍向布局发出原始 `nav` 路由目标。
3. calculation store 继续提供历史列表和当前 conversation id。
4. 历史打开、软删除确认和错误提示仍由布局编排，AppShell 只发出用户意图。
5. session store 继续提供头像与用户名，仅显示位置从顶栏移动到底部用户区。

本次不新增网络请求，不改变任何 API payload 或响应解析。

## 可访问性与交互

- 导航使用 `nav` 语义，当前项保留 `aria-current="page"`。
- 所有纯图标按钮提供 `aria-label`；不熟悉的紧凑态图标提供 tooltip。
- 折叠、抽屉打开、更多菜单和删除按钮可通过键盘操作。
- `:focus-visible` 使用清晰的 XC accent outline。
- 侧栏宽度过渡遵循 `prefers-reduced-motion`，用户选择减少动态时关闭位移动画。
- 窄屏抽屉管理焦点和背景交互，关闭后焦点返回菜单按钮。

## 测试与验证

### 单元测试

- 更新布局测试，断言没有顶部通栏 AppShell，品牌、用户与动态菜单均位于左栏。
- 更新侧栏测试，覆盖展开/紧凑切换、动态菜单渲染、当前项高亮和 `nav` 事件。
- 覆盖动态菜单与本地回退菜单的指定显示名、右侧“引擎 / MAP”标记，以及未指定菜单无标记。
- 保留并更新历史会话测试，覆盖功能导航位于历史列表之前、打开、更多菜单和删除事件。
- 更新品牌测试，断言唯一品牌 SVG 在新 AppShell 中使用，不再要求顶栏重复渲染。
- 删除或改写只针对独立 `AppRail` 的测试。
- 新增布局导航测试，覆盖从其他模块新建会话或打开历史后进入 `/home`。

### 构建与视觉验证

- 使用 `npm test` 运行前端全量 Vitest。
- 使用 `npm run build` 验证生产构建。
- 启动 Vite 后用真实浏览器检查至少 1440x900、1024x768 和 390x844 三个视口。
- 截图检查侧栏非空、菜单当前态正确、主内容没有被遮挡、文本不溢出、抽屉层级正确。

## 合同一致性

- 保持已批准的“投资分析工作台功能项 → 分隔线 → 历史会话”顺序。
- 历史列表仍只消费当前用户未删除会话；前端不改变用户过滤和 404 规则。
- 删除仍为二次确认后的软删除；本次不引入级联或本地硬删除。
- 首页刷新仍只加载历史列表，不自动打开历史会话。
- 不引入登录、RBAC、`systemSign` 或新的身份校验逻辑。

## 验收标准

- 首屏不再存在顶部通栏品牌栏，AppShell 完整位于页面左侧。
- 左栏视觉结构与参考图一致；菜单仍来自现有动态路由，并按路由应用已指定的展示名和“引擎 / MAP”标记。
- 品牌、新建会话、菜单、历史和用户信息形成一个连续、清晰的侧栏层级。
- 路由切换、历史回放、新建会话和软删除行为保持可用。
- 桌面、平板和手机视口无重叠、溢出或不可达控件。
- 相关测试、前端全量测试与生产构建通过。
