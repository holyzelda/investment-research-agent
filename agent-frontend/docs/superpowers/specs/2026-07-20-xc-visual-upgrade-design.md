# XC 视觉升级设计

**日期：** 2026-07-20  
**范围：** `agent-frontend` 首页、结果展示、参数调整与应用外壳的视觉升级。  
**状态：** 用户已确认设计，待用户审阅本文档后进入实施计划。

## 1. 目标与边界

将当前页面从平铺的深灰卡片界面升级为“**机构底 + signature 焦点**”的 XC 玄策风格：以近黑层级、克制边框、大号数字和充足留白构建专业投研工作台气质；仅在欢迎态、项目全投资 IRR 与主操作中使用 cyan-to-violet 的品牌渐变与低强度 glow。

本次仅改变视觉结构和样式，不改变以下内容：

- API、Pinia store、路由、测算任务及轮询逻辑；
- 参数字典驱动的参数显隐、锁定、范围、精度、暂存与重算行为；
- 结果快照结构、图表数据契约、ECharts 图表逻辑和颜色语义；
- `formatNumber` / `formatPrice` 的展示格式；
- 报告占位、版本选择、历史回放、软删除等现有交互。

## 2. XC token 与空间层级

在现有 XC token 基础上补充少量**派生 token**。所有新 token 的颜色仅基于已有 XC 深色面、品牌色、边框色和阴影色派生；组件样式继续只引用 `var(--xc-*)`，不引入内联 hex/rgb 或 Tailwind 颜色类。

新增层级用于区分：

1. 页面近黑基底；
2. 浮起容器面（侧栏、结果总容器、弹窗）；
3. 子卡面（基础信息、KPI、单个图表、参数分区）；
4. 弱强调面（选中、输入聚焦与低优先级交互）。

页面背景叠加极低透明度的品牌氛围光：左下 cyan、右上 violet。它仅在空白区域产生纵深，不影响文本对比度、图表阅读或表单操作。

## 3. 应用外壳与布局

- 顶栏提升至 64px，增加轻量品牌标识，优化标题字阶；用户区域采用低调胶囊或分隔表达。
- `AppRail`、历史侧栏、用户/助手气泡、输入框仅跟随新的 surface、border、shadow 和间距系统，不增加独立的强渐变或 glow。
- 对话消息列、结果卡和输入框共享响应式内容宽度；大屏最大约 1100px，小屏按可用视口收缩，避免水平溢出。
- 保留当前 rail、历史会话、会话折叠、版本滚动定位和输入操作行为。

## 4. 欢迎态

欢迎态保留“光球 + 渐变标题 + 输入框”的品牌结构：

- 光球保持当前素材和轻微浮动；若在实施验证中确认素材在大屏失真或观感不足，可替换为等占位的纯 CSS cyan/violet 多层辉光球。
- 渐变标题是欢迎态的唯一大型 signature；说明文案和示例胶囊降为次级视觉层。
- 增加上下留白，输入区成为正式的项目测算入口。
- 示例一键发送、文本输入及测算入口行为保持不变。

## 5. 结果报告卡

结果展示从“一张长卡 + 分割线”改为有节奏的机构式结果报告。

### 5.1 状态头

保留测算状态与版本号。使用极细的品牌强调线或弱渐变作为结果容器的唯一边界强调，不使用大面积渐变填充。

### 5.2 项目基础边界子卡

项目基础条件改为独立浮起子卡，保留省份、节点、装机功率、装机容量、充放电成本等数据与字段显示规则。通过宽松内边距、高一阶 surface、弱描边和软阴影建立层级。

### 5.3 核心投资收益子卡

五个 KPI 完整保留并整体放大。项目全投资 IRR 是唯一的视觉重点：使用品牌渐变数字和极淡 glow 边。其余 KPI 使用强文本或常规数字色，避免所有数字同色。

不修改 KPI 数据、顺序、单位或数字格式化规则。

### 5.4 收益深度分析

收益环图与偿债覆盖倍数图分别放入独立浮起子卡，并提供清晰小标题。仅改变容器、留白和标题层级；不改变：

- ECharts option 构造与生命周期；
- `--xc-chart-*` 分类色；
- 中国市场红涨绿跌语义；
- DSCR 的分段坐标轴、警戒线、辅助安全余量逻辑；
- 图表数据输入契约。

### 5.5 版本记录

右侧版本条的摘要指标由资本金 IRR 统一为项目全投资 IRR，使版本列表与结果主焦点一致。版本选择、最新标记、滚动定位和报告占位保持不变。

## 6. 参数调整与高级弹窗

参数区维持“可操作的专业工具”定位，并与结果报告共享卡片层级。

- Inline 参数调整区升级为浮起容器，项目、金融、收益等区域拥有明确的分区容器或小卡；滑块、数值输入和动作区统一留白与对齐。
- 高级参数弹窗采用高阶浮起 surface；金融、收益、成本分区各自采用子卡呈现。
- 主操作继续使用 XC 渐变按钮；次操作保持低调描边或透明样式。
- 控件类型、范围、只读状态、delta 提示、参数暂存、受控覆盖和重新测算流程完全不变。

## 7. 响应式与可访问性

- 所有多列结构在可用宽度不足时平滑切换为双列或单列；不得压缩文字、按钮或图表到不可读状态。
- 保留现有可见焦点环、键盘版本选择、禁用状态和 `aria-*` 语义。
- 图表容器必须在尺寸变化时继续由现有 ECharts 生命周期封装响应更新。

## 8. 验证策略

实现阶段须执行：

1. 相关 Vitest 测试，覆盖首页输入、任务流、版本切换、历史回放、参数调整与图表；
2. `pnpm test` 全量回归；
3. `pnpm build`；
4. 实际 UI 流程验证：欢迎态、首次测算、版本选择、参数重算和窄视口布局。

如视觉重构使仅验证静态 DOM/class 的测试断言过期，可以同步更新断言；不得借此改变既有业务行为或契约。

## 9. 非目标

本次不新增报告功能、地图模块、政策模块、后端接口、数据模型、主题切换能力或新的设计体系依赖。
